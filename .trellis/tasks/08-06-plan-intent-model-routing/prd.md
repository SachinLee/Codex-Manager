# 规划意图模型路由扩展

## Goal

在同一 OMP 主会话中，用户发出直接的规划请求时自动锁定规划状态：解析有效配置的 `modelRoles.plan`、切到该角色对应的具体模型，并持续注入“只规划、不实现、等待批准”约束；仅在明确批准实施或退出规划时，解析 `modelRoles.default` 并切回默认执行模型。无关旁问不得解除该状态。

## Confirmed Facts

- OMP 的扩展 `input` 事件提供 `event.text`、图片和来源；输入可被改写，但本需求不改写用户原文。
- OMP 已公开 `ctx.models.resolve(spec)`：它按当前有效 settings 解析角色别名（如 `@plan`、`@default`）为已认证的具体模型；`pi.setModel(model)` 异步切换会话模型，并在目标缺少可用认证时返回 `false`。
- 有效设置按运行时覆盖、CLI overlay、项目 `.omp/config.yml`、全局 `~/.omp/agent/config.yml` 的优先级合并。当前有效全局配置包含 `modelRoles.plan` 与 `modelRoles.default`；扩展不得硬编码任何 provider、模型 ID 或配置文件路径。
- 仓库已有 `.omp/extensions/trellis/index.ts`，使用 `input`、`before_agent_start` 与 `context` 事件维护工作流提示；尚无模型路由扩展。
- OMP 支持用 `pi.appendEntry(...)` 写入命名空间化自定义会话条目，并在 `session_start` / 分支切换时由 `ctx.sessionManager.getBranch()` 恢复状态。

## Requirements

1. 以会话级状态机处理 `inactive` 与 `planning`，而不是按单条消息做无状态分类。
2. 仅把直接、自然语言中的规划请求作为进入触发；计划候选包含“规划方案”“修改方案规划”“技术方案”“实施计划”“帮我计划”和英语 `plan this` 等同义表达。
3. 代码块、引用文本、否定表达（如“不要规划”）和非请求性质的方案讨论不得触发进入；已进入时，旁问、引用、历史回顾和普通对话必须保持 `planning`。
4. 进入时用 `ctx.models.resolve("@plan")` 解析有效角色配置，成功后调用 `pi.setModel(...)`；不可用、无认证或切换失败时不得伪造进入状态，并向用户给出可操作错误。
5. 每次规划状态下的主代理启动前均注入隐藏约束：只做分析/方案，不编辑、不执行实现，明确等待用户批准。该约束在会话压缩后仍有效。
6. 仅对明确的“批准实施”“开始实现”“退出规划”及其稳定同义语退出；退出时用 `ctx.models.resolve("@default")` 和 `pi.setModel(...)` 切回默认模型。任何其它输入均不切回。
7. 状态变迁必须以命名空间化会话条目持久化，能在恢复、切分支与压缩后重建；重复进入或重复退出必须幂等且不重复写入提示。
8. 退出、进入及解析失败均须在交互 UI 中给出简短可见状态；非交互/RPC 来源不得依赖 UI 才能保持正确状态。

## Acceptance Criteria

- [ ] 对每个给定的直接规划样例，下一次主代理调用使用运行时解析的 `@plan` 模型；代码中没有具体 provider 或模型 ID。
- [ ] 代码块、引用段、否定句和仅讨论既有方案的输入不会进入规划状态。
- [ ] 规划状态下的无关旁问不会切换模型或丢失“只规划”约束。
- [ ] 只有批准/开始实现/退出规划触发的输入会使状态退出并将模型切回运行时解析的 `@default`。
- [ ] `@plan` 或 `@default` 无法解析、无认证或 `setModel` 失败时，状态与模型保持原样且用户获得失败原因。
- [ ] 恢复会话、切换分支或压缩后，规划状态和约束仍与最后一个持久化状态一致。

## Out of Scope

- 不修改 OMP 内置 plan mode、模型角色配置或模型选择 UI。
- 不用 LLM/网络请求对每条输入做意图识别，也不修改用户原始消息。
- 不把任意“方案”一词或历史文本解释为进入或退出指令。

## Open Question

- “历史讨论”需被定义为可测试的文本边界：是仅排除引用/代码和不含当前请求的回顾叙述，还是还要维护一组历史回顾短语。此决定直接影响误触发率与召回率。

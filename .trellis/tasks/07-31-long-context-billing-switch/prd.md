# 长上下文计费开关与 GPT-5.6 价格校准

## Goal

让管理员能够明确控制本地价格目录是否对长上下文请求应用阶梯价格，并使 GPT-5.6 的内置官方价格与 OpenAI 当前公开价格一致。管理员需要在扣费、日志、本地估算和额度预测中得到同一口径，且不得改变上游实际费用或历史账单。

## Confirmed Facts

- 模型目录可保存基础价格与任意长上下文阶梯；`model_price_tiers.min_input_tokens` 是触发阈值。
- `request_charge_snapshots` 的本地扣费已按输入 token 选择最高匹配阶梯，且快照保存命中的阈值与价格；已存在记录不会重算。
- 日志本地估算及配额/余额预测也各自从模型价格目录读取阶梯，但请求定价快照目前未显式标记此次是否命中长上下文档。
- 上游返回 `base_cost_override_microusd` 时，上游实际费用优先于本地模型目录计算。
- OpenAI 当前文档规定 GPT-5.6 在输入超过 272K tokens 时，输入和缓存输入按 2x、输出按 1.5x 计价。当前内置 Terra/Luna 价格仍为旧值。

## Requirements

1. 新增全局持久化设置 `longContextBillingEnabled`，默认启用，并通过现有 App Settings RPC 同时支持桌面端与 Web service-mode。
2. 开启时，本地计费、日志本地估算、API Key 用量及余额/配额预测按模型的长上下文价格阶梯计算；只有输入严格超过模型阈值时才命中长档。
3. 关闭时，上述本地计算强制选择基础价格档（`minInputTokens = 0`），即使模型定义了长上下文阶梯。
4. 上游报告的实际费用必须继续优先，不受该开关影响。
5. 每个新请求的价格审计数据必须能显示基础档、长上下文档或“长上下文计费已关闭”，并记录命中阈值；历史快照不变。
6. 新迁移仅更新未被用户编辑的内置 GPT-5.6 模型价格，并保留自定义模型、自定义价格和路由。
7. 使用当前 OpenAI 公开价格（美元 / 百万 tokens）：
   - `gpt-5.6-sol`: 基础 `5 / 0.5 / 30`，长上下文 `10 / 1 / 45`。
   - `gpt-5.6-terra`: 基础 `2 / 0.2 / 12`，长上下文 `4 / 0.4 / 18`。
   - `gpt-5.6-luna`: 基础 `0.2 / 0.02 / 1.2`，长上下文 `0.4 / 0.04 / 1.8`。

## Acceptance Criteria

- [ ] 设置页提供“长上下文阶梯计费”开关，默认开启，刷新应用后状态保持一致。
- [ ] 开关开启时，272,000 tokens 恰好使用基础档，超过阈值才使用长档；各计费/估算面得到一致金额。
- [ ] 开关关闭时，超过阈值的本地请求仍使用基础档，且新快照标明该原因。
- [ ] 上游实际费用存在时，开关不改变其基础费用或商业倍率后的收费。
- [ ] 新的 GPT-5.6 内置价格和长上下文档与上述官方价格一致；用户编辑过的模型/价格不被覆盖。
- [ ] 现有请求快照和账本不回溯变更；重复写入同一请求仍保持幂等。
- [ ] 核心存储和服务层定向测试通过，前端构建通过。

## Out Of Scope

- 不修改模型路由、上游请求载荷或供应商侧价格。
- 不自动从供应商网站抓取、写入价格。
- 不回填或重算历史请求、账本、额度或日志。
- 本期不为每个模型单独设置开关；模型级的阈值与三档价格继续由模型目录管理。

## Decisions

- 开关默认开启，以维持当前官方价格阶梯的正确计费语义；关闭是管理员主动选择使用基础档的兼容模式。
- 开关是全局 App Settings，而非路由设置。路由不应改变计费语义。
- 上游实际费用权威性高于本地估算。
- 价格以模型阶梯值表达，不将“2x / 1.5x”写死为全局倍率，以支持不同供应商的不同规则。

## Open Questions

无。用户已确认默认开启策略和本期范围。

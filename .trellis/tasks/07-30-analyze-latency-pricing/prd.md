# 分析请求日志延迟与长上下文计费

## Goal

确认请求日志页能否按首响时间提供清晰、可解释的颜色标记，并核对 Codex Manager 对长上下文请求的 Token 与费用计算是否与上游账单口径一致。

## Background

- 当前页面已展示 `总用时 / 首响 / 输出速率`；首响来自服务端 `first_response_ms`，但目前只使用统一主色文本，没有慢首响颜色语义。
- 当前运行时数据库的 GPT-5.6 价格迁移已应用，存在 `272000` 起的长上下文阶梯；Sol/Terra/Luna 的输入与缓存价为标准价 2×，输出价为标准价 1.5×。
- 运行时数据库中，截图对应的长上下文请求已按长档位持久化；截图中的上游 `$0.34` 与长档位相符，而本地截图的 `$0.196738` 与标准档位相符。完整复算见 `research/findings.md`。

## Requirements

1. 定位请求日志中首字、总耗时和颜色呈现的前后端数据链路，确定当前状态及最小改动方案。
2. 定位本地使用量和费用计算链路，重点核对输入、缓存、输出 token 与长上下文阈值/倍率。
3. 将本地计算公式与截图中的上游单笔数据逐项对照，区分已证实事实与无法从截图单独证明的推断。
4. 请求日志费用列不再展示 `pricingCostSource === "local_estimate"` 的“本地估算”标签；费用数值及其他计费提示保持不变。
5. 请求日志的首响数值按原始 `firstResponseMs` 分级：≤10 秒绿色、>10–20 秒橙色、>20–30 秒黄色、>30 秒红色；缺失值保持中性色。总耗时和输出速率不参与该颜色语义。
6. 优化请求日志表的会话标题可读性，改善中文标题与会话 ID 在高密度表格中的视觉层级，同时保留单行截断与完整信息悬停提示。
7. 实施已确认的请求日志前端优化，并以针对性测试、浏览器用例和生产构建验证结果。

## Confirmed Facts

- 过去 24 小时的 980 条请求日志中，944 条具有 `first_response_ms`；分布为 ≤2 秒 245、2–5 秒 346、5–10 秒 121、>10 秒 240、缺失 36。
- 当前持久化费用从不可变 `request_charge_snapshots` 写回 `request_token_stats.estimated_cost_usd`；按 272K 长上下文档位复算后，与抽样记录逐分一致。
- 费用展示可以同时区分“官方上游实际费用”“本地估算”“基础费用 / 商业倍率”，但 GPT-5.6 长上下文档位本身不是商业倍率，而是模型价格阶梯。

## Out of Scope

- 不在未经用户确认的情况下修改请求日志 UI 或费用计算。
- 不调整上游供应商的计费规则。
- 不推断截图中未给出的模型定价或上游隐藏字段。

## Confirmed Implementation Scope

- 前端改动限定在 `apps/src/app/logs/page-sections.tsx` 及其请求日志测试；无需新增 API、RPC 字段或数据库迁移。
- 首响颜色应只附着在首响数值本身；阈值判断必须使用未格式化的毫秒值，确保边界一致。
- 会话标题由 `apps/src/app/logs/page-cells.tsx` 的 `SessionInfoCell` 渲染；当前主标题为 `11px font-medium`，次级会话 ID 为 `9px font-mono`，列内容实际可用宽度约 168px。
- 会话标题优化保持为纯样式与布局调整：不改变会话匹配、搜索、会话 ID、来源、路由锚点或 Tooltip 内容。

## Implementation Results

- 已移除费用列的“本地估算”标签，保留费用数值、“官方实际费用”及其他计费提示。
- 已按原始 `firstResponseMs` 为首响数值应用四档颜色，缺失或非有限值使用中性色。
- 已将会话主标题调整为 12px / 16px 行高，将会话 ID 调整为低对比度 10px 等宽文本。
- 请求日志源码回归测试、针对性 ESLint、生产构建和请求日志 Playwright 用例通过。
- 全量 `test:runtime` 的本次请求日志用例通过，但仍有 3 个与本任务无关的既有失败：聚合 API 冷却源码断言 1 个、英文翻译覆盖断言 2 个。

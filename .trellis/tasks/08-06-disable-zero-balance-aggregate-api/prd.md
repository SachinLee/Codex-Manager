# 余额为零时禁用聚合 API

## Goal

当某个聚合 API 的可查询余额为零时，暂时将它从路由候选中排除，避免把请求发送到无余额的上游；余额无法查询的 API 不受该规则影响。管理员必须能手动解除这项临时禁用，以应对余额刷新滞后或查询结果过期。

## Confirmed Facts

- `crates/service/src/aggregate_api.rs::refresh_aggregate_api_balance` 是单项 RPC、配额批量刷新与后台轮询共用的唯一余额查询结果边界。
- 只有 `ok == true`、`balance.is_valid == true` 且 `balance.remaining == Some(0.0)` 才可靠表示本次查询确认了零余额；未启用查询、查询错误、无余额值或无效快照都不是零余额。
- 当前余额结果只持久化在 `aggregate_apis.last_balance_*`，不参与候选路由；最终候选在 `crates/service/src/gateway/upstream/protocol/aggregate_api.rs::proxy_aggregate_request` 中才筛除失败冷却/健康状态。
- 显式 `AggregateApi.status`、失败冷却 `AggregateApiRuntimeStatus`、持久化 health 状态已有各自的路由/重置语义。既有 runtime/health reset 会清理其它状态，不能用于本功能。
- 余额查询已跨服务重启持久化，但零余额专用路由状态、RPC、类型、UI 和手动解除目前均不存在。
- 管理页面已经有独立运行状态列、确认对话框、typed RPC/Tauri/Web transport 和 admin-only service access-control 链，可按相同形状扩展，但不得复用“冷却”语义。

## Requirements

### R1. 基于可用余额的临时路由禁用

- 聚合 API 余额查询得到零余额时，服务应将该 API 标记为临时不可路由并从后续候选中排除。
- 无余额查询能力、查询结果缺失或查询失败的 API 不得因本规则被禁用。
- 该状态必须与既有配置启用状态、失败冷却状态区分，避免互相覆盖或误报。

### R2. 手动解除

- 管理员可对被余额规则暂时禁用的单个聚合 API 执行手动解除。
- 解除后该 API 在其他路由条件允许时立即重新成为候选；后续余额检查仍可按规则重新禁用。
- 操作成功或失败必须有明确反馈，且桌面端和 service-mode Web UI 语义一致。

### R3. 状态恢复规则

- 已确认的零余额临时禁用只由两种事件解除：下一次成功、有效且余额大于零的查询，或管理员的手动解除。
- 查询失败、无余额值或无效快照不得新建零余额禁用，也不得解除此前已确认的零余额禁用。
- 手动解除仅撤销当前零余额临时禁用；该 API 保持已解除，直至下一次成功、有效的零余额查询再次触发禁用。
- 零余额临时禁用与手动解除必须跨服务重启保留；服务重启不得因为丢失进程内状态而重新路由到已确认零余额的 API。

### R4. 可观察性与安全边界

- 管理界面应清晰说明该 API 因零余额而被临时排除，并提供解除入口。
- 不向浏览器返回 API secret、原始上游响应或鉴权信息。
- 余额查询的上游错误 body、`message`/`error` 字段、header、token 和鉴权参数不得写入 `last_balance_*`、零余额状态、请求日志、RPC 返回或 UI toast；仅可保留稳定的安全分类与 HTTP 状态。
- 新能力必须沿用 typed API/RPC/transport 和既有服务访问控制。

## Acceptance Criteria

- [ ] 已知余额为零的启用中聚合 API 不再出现在其余健康条件满足的路由候选中。
- [ ] 未配置余额查询或查询失败/无结果的聚合 API 继续按既有路由规则参与候选。
- [ ] 管理员能看见“因零余额临时禁用”的状态并手动解除单个 API。
- [ ] 手动解除后，该 API 在未被配置停用、冷却或其他策略排除时重新参与路由。
- [ ] 手动解除的结果在桌面端与 service-mode Web UI 中一致，且错误不会静默吞没。
- [ ] 不改变已有显式启停、失败冷却、余额查询之外的路由行为。
- [ ] 查询失败、无余额值或无效快照不会解除此前已确认的零余额禁用；下一次成功有效的正余额查询会解除它。
- [ ] 服务重启后，未被手动解除或有效正余额清除的零余额禁用仍生效；手动解除同样跨重启保留。
- [ ] 含伪造 token 的余额上游错误响应不会出现在 SQLite 缓存、聚合 API 列表/RPC、请求日志或桌面/Web UI；管理员只看到安全的分类反馈。

## Scope Boundaries

- 不在本任务中新增余额查询供应商适配器。
- 不将查询不到余额等同于零余额。
- 不修改 API secret 存储或向 UI 暴露敏感配置。

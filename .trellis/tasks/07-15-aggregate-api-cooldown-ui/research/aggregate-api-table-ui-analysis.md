# 聚合 API 表格界面分析

## 参考界面

- 用户提供的当前聚合 API 表格截图，约 `1644 × 664`。
- 页面实现：`apps/src/app/aggregate-api/page.tsx`。
- 当前表格使用 `table-fixed`；除第一列外，其余列大多设置了固定宽度，因此第一列会吸收剩余空间。
- 截图中第一列约占整张表格的三分之一，但其内容已经使用单行截断与 Tooltip，实际无需保留这么大的常驻宽度。

## 推荐布局

列顺序调整为：

`供应商 / URL` → `类型` → `密钥` → `顺序` → `测试连通性` → `余额` → `今日使用` → `Guard` → `路由状态` → `启用` → `操作`

- 第一列建议固定在 `280–320px`，以 `300px` 作为桌面基准。
- 新增“路由状态”列建议 `168–184px`，以 `176px` 作为基准。
- 现有“状态”列改名为“启用”，保留开关行为及约 `96–112px` 宽度。
- 窄窗口继续依赖页面现有表格横向滚动/固定操作列策略，不通过压缩字号或增加行高来硬塞内容。

## 单元格状态

### 可路由

- 绿色状态点或轻量 badge：`可路由`。
- 默认不展示重置入口。
- 失败计数若未达到阈值，可放入 Tooltip/Popover，避免正常行产生持续噪声。

### 冷却中

- 橙色轻量 badge：`冷却中 04:12`。
- 第二行：`连续失败 5/5`。
- 紧凑次级操作：`解除冷却`。
- 最近失败原因、最后失败时间、冷却截止时间放在 Tooltip/Popover；错误内容必须经过服务端结构化/脱敏，不直接展示原始响应体或 secret。
- 可给单元格或行首增加非常淡的橙色强调，但不建议整行使用高饱和背景，以免覆盖余额、Guard 等现有告警色。

## 交互建议

- 点击 `解除冷却` 打开确认弹窗，明确说明“该 API 将立即重新加入路由候选；若上游仍异常，可能再次失败并进入冷却”。
- 成功后立即更新本地查询缓存并刷新运行时状态；失败使用现有 toast 展示。
- 冷却倒计时在前端按 `cooldownUntil` 本地每秒计算；后台 runtime snapshot 可按约 2 秒轮询，不必让整个配置列表高频刷新。

## 视觉结论

独立“路由状态”列比把冷却 badge 塞进供应商单元格更适合这张现有表格：第一列存在足够的可回收空间，并且独立列能清楚区分“测试已连通”“当前可路由”“配置已启用”三个不同概念。

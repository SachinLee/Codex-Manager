# API 模型发现与路由配置

## Goal

管理员在“模型与路由”页面可以针对每个已保存的聚合 API 请求一次上游模型目录，并在按 API 标识的结果中看到该 API 当前支持哪些模型；本功能只读查询和展示，不写入模型目录、路由或任何持久化数据。

## Confirmed Facts

- 聚合 API 当前在 `apps/src/components/modals/aggregate-api-modal.tsx` 中配置 URL、认证方式和密钥；新建 API 保存后才获得其 `id`。
- 本地模型目录 V2 是唯一的路由配置来源；每条聚合 API 路由由 `(sourceKind="aggregate_api", sourceId, upstreamModel)` 表示，且上游模型名目前完全手填。
- `ModelCatalogModal` 明确提示“这里不会访问供应商 `/models`”。
- 后端能力诊断已经以保存的 API 凭据向 `<base>/models` 发起认证 GET 请求，但只记录 HTTP 探测状态，不解析或返回模型列表。
- 项目中有未接入前端/RPC 的旧 `aggregate_api_supplier_models` 表和类型；其以供应商名作为键，不能表达同一供应商下不同 URL 或认证配置的实时发现结果，因此不能直接作为新功能的事实来源。
- API 密钥、用户名和密码只能由服务端读取和注入上游请求；模型发现响应及错误不得回显认证信息或完整上游响应体。

## Requirements

1. “模型与路由”页面提供按聚合 API 分组的上游模型发现面板；每条结果必须显示 API 的稳定身份信息（API ID、供应商名称、provider 类型，必要时显示脱敏后的 URL），不能把不同 API 的模型混在一起。
2. 管理员可以单独刷新某个 API，也可以触发“获取全部 API 模型”；批量获取应逐 API 产出结果，某个 API 失败不得覆盖或隐藏其它 API 的结果。
3. 每个 API 的发现操作请求该 API 的 `/models` 端点，并沿用该 API 已保存的认证配置和网络代理策略；新建 API 必须先保存。
4. 操作返回结构化、去重、可展示的发现结果，至少包含 API ID、模型 ID、可选显示名、发现时间、HTTP 状态及可操作的错误摘要；不保存密钥、认证头或未脱敏响应体。
5. 发现操作只读查询和展示，不自动创建本地模型、不修改本地模型、不新增路由、不修改供应商配置、不启用模型。
6. `/models` 端点不存在、认证失败、响应不是可识别的模型目录、网络超时或返回空目录时，保留该 API 当前展示状态和本地目录，并显示区分原因的失败/空结果。
7. 发现结果只存在于当前“模型与路由”页面的内存状态；离开页面、刷新页面或重启应用后丢弃，不新增数据库表、迁移或后台同步任务。

## Acceptance Criteria

- [ ] 每个已保存聚合 API 在发现面板中拥有独立结果区，结果区明确显示对应 API 的身份；不同 API 返回同名模型时仍能区分来源。
- [ ] 单独刷新一个 API 后，该 API 的模型列表、状态、时间和错误被更新，其它 API 的结果保持不变。
- [ ] 点击“获取全部 API 模型”后，每个 API 都得到成功、空目录或失败状态；一个 API 的失败不会阻止其它 API 完成展示。
- [ ] 发现不会新增本地模型、修改现有模型、修改路由、更新供应商配置或启用任何模型。
- [ ] 对 401/403、404、超时、不可解析响应和空目录，UI 显示可操作结果，且不泄漏密钥、认证头、查询参数或完整上游响应。
- [ ] 离开“模型与路由”页面或刷新后，发现结果不会从服务端或本地缓存自动恢复。
- [ ] 桌面和 Web/service-mode 均通过既有 typed transport/RPC 链路调用同一服务端实现。

## Out of Scope

- 将发现结果用于自动或手动填充模型路由；本任务只负责查询和展示，路由仍由现有手工配置流程负责。
- 自动导入上游模型的价格、上下文窗口、能力、指令或供应商元数据。
- 自动创建本地模型、自动分配路由、后台周期性刷新或请求转发时实时查询 `/models`。
- 将发现结果持久化、写入 `aggregate_api_supplier_models` 或任何新的缓存表。
- 更改网关的模型路由、失败切换、能力诊断或供应商认证语义。

## Key Decision

- 发现入口放在“模型与路由”页面，按 API 独立展示；本任务不修改模型路由编辑器。
- 结果按 `aggregateApiId` 建立内存索引，并在 UI 中始终显示 API 身份；同名模型不会被错误合并。
- 提供单 API 刷新和获取全部 API 两种入口；批量操作逐 API 隔离状态，避免一个供应商异常导致整体无结果。

## Blocking Decision

- 无。

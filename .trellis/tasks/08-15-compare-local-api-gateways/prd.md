# 比较本地 API 网关

## Goal

为 Windows 11 本机上的个人 AI 网关使用，比较 CodexManager 与 `D:/my-works/sub2api`；重点判断哪个更适合管理多个上游 API，并在失败时自动切换，同时尽可能降低日常运行的操作和资源成本。

## Current behavior and problem

- 使用者当前以 CodexManager 作为网关，已接入多个上游 API，并依赖自动降级避免人工切换。
- 需要确认 sub2api 是否能以更低的本地成本提供同等或更合适的路由体验。

## In scope

- 两项目的本地部署前置条件、常驻进程与数据服务依赖。
- 上游账号/API 的调度、健康状态或故障切换能力。
- 对个人、单机、Windows 11 使用的日常配置和维护成本。
- 从源码、项目文档、当前本机可观察进程和可执行产物得出的资源证据；无法安全复现的负载数据明确标为未测量。

## Out of scope

- 对上游账号、服务条款或商业模式的合规性作判断。
- 多租户销售、支付、公开互联网部署、高可用集群与压力基准测试。
- 修改任一项目的源码、配置或本机运行中的网关。

## Actors and affected systems

- 单一 Windows 11 个人用户。
- CodexManager 桌面/服务版与其多个第三方聚合 API 上游。
- sub2api 后端、前端及其 PostgreSQL、Redis（若采用官方部署形态）。

## Assumptions and constraints

- 决策优先级：自动降级和可用性不倒退；其后是少占内存、少进程、少运维；最后才是功能广度。
- 仅以当前本地检出的源码和可观察运行状态为事实来源；不把 README 的赞助商宣传作为功能证据。

## Acceptance criteria

### AC-001: 比较可复核

- 场景：为个人 Windows 本机选择网关。
- 动作：按部署依赖、日常操作、故障切换、常驻资源四个维度核查两项目。
- 预期：结论逐项引用本地源码、配置或进程观察；推断和未测量项明确区分。
- 必须不：不得把未验证的宣传或外部推荐当作技术事实。
- 验证方法：任务研究记录与文件/命令证据。

### AC-002: 给出可执行取舍

- 场景：现有 CodexManager 已配置多个上游并在使用自动降级。
- 动作：基于 AC-001 的证据选择更适合的默认方案。
- 预期：明确推荐保留、迁移或并行使用之一，并说明决定条件和最小资源运行形态。
- 必须不：不得因功能列表更长而建议牺牲个人本机资源目标。
- 验证方法：可将建议直接映射到项目支持的启动与配置方式。

## Open or blocking decisions

无。默认按“Windows 本机、单用户、不引入 Docker/WSL/外部数据库，除非其带来不可替代的自动降级能力”进行比较。

# 目标

完成请求日志页面的查询条件与右侧统计模块的改造设计和实施规划：将现有“一个输入框 + 前置条件类型选择”的查询方式改为独立字段；在筛选结果统计中显示缓存率。

# 现状与问题

用户观察到请求日志查询条件以单一输入框配合前置类型选择呈现，切换和组合查询效率低。右侧统计模块目前展示请求次数、成功/异常次数、筛选结果数、累计 Token 与累计费用，但未展示筛选结果的缓存率。

# 范围内

- 请求日志页面筛选条件的 UI、状态和查询参数设计。
- 独立展示“标题”文本输入、“模型”下拉选择、“平台秘钥”下拉选择。
- 右侧统计模块增加筛选结果缓存率展示。
- 明确缓存率的计算口径、无可计算样本时的呈现与现有筛选条件的兼容性。

# 范围外

- 修改请求日志的采集、持久化 schema、网关缓存逻辑或既有历史数据。
- 新增筛选字段以外的日志分析、导出或图表能力。
- 改动请求日志页面以外的页面视觉重构。

# 角色与受影响系统

- 管理员/操作者：在请求日志页面筛选并查看本次筛选结果的聚合统计。
- `apps/` 前端：查询控件、URL/状态、日志 API 调用与统计卡片呈现。
- 请求日志服务/API：确认可用筛选字段和缓存 Token 聚合数据是否已存在；若无，设计最小服务端统计扩展。

# 假设与约束

- 页面继续沿用仓库现有的组件、玻璃主题和 typed API/transport 约定。
- “平台秘钥”使用产品当前对平台/API key 的既有命名和数据源，不新建凭据管理模型。
- 缓存率必须基于筛选结果的数据计算，不是页面所有日志的全局缓存率。
- 缓存率口径已确认：`cached_input_tokens / input_tokens`，不包含 `cache_write_input_tokens`；输入 Token 为零时显示 `-`。
- 模型下拉选项已确认来自 `StartupSnapshot.apiModels` 平台模型目录。
- 标题输入已确认复用现有 session title lookup，匹配标题、父标题和会话 ID。

# 领域术语

- 标题：请求日志当前可供查询和显示的标题/会话标题字段，使用 session title lookup 后按会话 ID筛选。
- 模型：日志记录的模型标识，选项来自平台模型目录。
- 平台秘钥：日志所属的平台/API key 维度，使用既有 API key 列表；仅显示名称或紧凑 ID，不展示 secret。
- 缓存率：当前筛选结果的 `cached_input_tokens / input_tokens`，输入 Token 为零时显示 `-`。


# 验收标准

- [x] AC-001: 独立显示并应用查询条件
  - 场景：操作者打开请求日志页面。
  - 动作：查看并设置标题、模型、平台秘钥条件，单独修改或组合修改后执行现有查询。
  - 期望：标题为独立输入框，模型和平台秘钥各为独立下拉框；每个条件独立写入现有查询状态并共同限制结果。
  - 不得：保留要求先选类型才能输入的单一复合查询交互；不得改变未设置条件时的现有结果。
  - 验证方法：页面运行时手工验证及相关前端测试/构建。

- [x] AC-002: 展示筛选结果缓存率
  - 场景：操作者以任意筛选条件查看右侧统计模块。
  - 动作：等待当前筛选结果的统计数据加载完成。
